# 原定四个缺口：实施与验证指南

**本页与 `references/08-evidence-matrix.md` 配套**。不能将创作者访谈、视频基准、剧本续写基准的结论当作本 Skill 的直接实验结果。

## 缺口一：论文解析能否稳定获得正确素材？
**技术选择**：优先用可提取页码、章节、引用位置的 GROBID 处理科研原生 PDF（TEI XML）；复杂表格、公式或多栏版式可补充 Marker 的 Markdown/JSON 提取，并允许原图回查。GROBID 和 Marker 都是候选 parser，不是本项目已经部署的模块。

**检查协议**：每篇论文至少核查被选中候选所涉及的原始段落/图表：①页码及图号是否能定位；②主语、样本与实验条件是否一致；③相关/因果、假设/结论、定性/定量是否区分；④关键否定词/限定词是否丢失。对不能核实的卡标 `unverified`，不得作为支持性结论传播。

**指标（待测试）**：候选卡原文定位成功率、已知命题类型混淆次数、图表误读次数、人工核查时间；不使用没有样本依据的“必须 98%”门槛。

来源：https://github.com/grobidOrg/grobid ；https://github.com/datalab-to/marker

## 缺口二：多个有趣素材如何选择一个？
先“广泛扫描”，再按四项判断**分别记录证据**：现实/情感关联，好奇缺口，是否可通过人物行动变成故事，是否需要扭曲论文事实才能编出戏。拒绝仅凭一个合成高分选取；记录保留/淘汰理由，最终冻结一个核心问题。

**对比实验**：同一论文分别走①摘要直接写 Hook ②PaperTok 式核心发现/Hook 发散 ③趣味素材→戏剧种子（本方案），请盲评者分别评价吸引力和实际可发展剧情的能力；事实核验由独立评审完成。

来源：https://arxiv.org/html/2601.18218

## 缺口三：何时应该回去修改故事，而不是美化分镜？
按最早原因定位：无人物动机/事件无后果/Hook 未兑现，回**故事节拍**；人物对话内容错误回**剧本场景**；定位/道具/服装不一致回**资产/分镜**；画面违背本来清晰的动作提示只回**模型适配/该镜重生成**。每次修正保留未受影响的成果。

**审查结构**：每条缺陷具备 `source_stage`、`evidence`、`target_id`、`severity` 和 `patch_scope`，无需复制论文中的复杂三模型仲裁架构；仅重大或有分歧的争议再二次审查。

来源：https://arxiv.org/html/2605.22144 ；https://arxiv.org/html/2609.00646 ；https://arxiv.org/html/2610.00097

## 缺口四：怎样评价观众真的觉得有趣？
不以单一大模型“趣味性=9分”冒充受众事实。采用**分开测量吸引、看懂、误解、探索**的方案：
1. 首 3–5 秒后是否愿意继续看（行为选择/续看意愿评分），并记录观众理由；
2. 故事播放后的有趣程度、人物行动因果理解与具体喜欢/不喜欢的镜头；
3. 视频后给出真实论文标题/摘要入口，记录想进一步了解的意愿与实际点击（两者区分）；
4. 使用 2–3 项事先制定的论文事实判断题，确认剧情是否造成把推演当证据的误解；
5. 以片段位置记录弃看点、困惑点和信息缺口不兑现之处。

**最小实验建议**：按相同论文、长度区间、生成成本条件比较 Direct、Hook-only、Full 三条路线，对受众随机呈现顺序并盲化生成条件，论文及作品做交叉随机化；报告观众差异和具体失败案例。不声称某固定频率的反转最优。

**注意证据限制**：Audience in the Loop 是短剧创作者的主观访谈；DramaBench 的人—模型一致性在叙事效率和角色一致性两项不显著，因而尤其不能只靠单个 AI judge 自动确定「哪个故事更有趣」。

来源：https://arxiv.org/html/2602.14045v1 ；https://arxiv.org/html/2512.19012
