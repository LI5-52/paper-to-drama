# P2–P3 戏剧种子、核心问题与三种风格匹配

## 关键区分
- `research_anchor`：来自论文的事实或问题，可能并非确定结论。
- `interest_angle`：为什么观众好奇、吃惊、共情、好笑。
- `drama_seed`：让一个角色在虚构情境里面对这个议题的目标、阻碍、选择、后果。
- `core_question`：驱动**整部**短剧的一个问题；只冻结一个。
- `hook`：开场的具体事件、话语或画面承诺；不是科学研究结论。

## 选择一个核心问题
对候选种子进行逐项口头/文字证明：①来源确实存在 ②不需要歪曲才能戏剧化 ③能用角色行动表达 ④有可兑现的开场承诺 ⑤能在目标时长内闭环（或刻意悬念）⑥制片约束可接受。没有明显冲突时优先设计**任务、试错、误会、关系变化、解谜、拟人化或轻喜剧**，不要强制反派、逆袭或惊天反转。冻结 `core_question_id` 与 `why_chosen/why_not_others`。

## 风格四轴，不把套路混成一类
- `world`：青春校园 / 现代职场 / 都市生活 / 古装架空 / 近未来 / 奇幻等。
- `genre`：轻喜剧 / 心理悬疑 / 情感 / 权谋 / 冒险 / 治愈 / 黑色幽默等。
- `dramatic_engine`：信息差 / 选择困境 / 规则试错 / 误会解除 / 身份错位 / 机制解谜 / 价值冲突等。
- `visual_mode`：真人电影感 / 2D 漫剧 / 定格 / 风格化 3D 等；这决定制作形态，不等同叙事类型。

## 生成三个候选的步骤
1. **共享同一 `core_question_id`**，以此生成三个不同的 `story_engine`（建议至少在机制/行动目标/障碍中有两方面实质差异）。
2. 对每个写：临时片名、观众期待、3–6 秒开场画面钩子（只是探索默认）、角色目标、阻碍、关键选择、情节与结尾预期、推荐理由、制作难度、事实误解风险。
3. 三者比较：同一故事仅换古装与职场场景 → 视为不合格；三种风格都依赖不存在的研究结论 → 不合格；都符合论文但情节完全不能行动 → 重新种子构建。
4. 按观众可读方式输出三个短卡片：`title, style_label, premise, opening_hook, why_fit`。内部保留事实卡/创作边界/复杂度，不泄露为用户步骤。
5. 等待用户只选择一次。之后固定风格与核心问题，除自动审查有重大问题或用户明确修改，不悄悄换主题。

## 不采用硬编码学科映射
禁止“心理学 → 校园”“医学 → 医疗剧”“设计学 → 职场”等机械规则。论文特征与戏剧机制相匹配，再由可理解度、受众关联、视觉可实现性共同决定故事世界。
